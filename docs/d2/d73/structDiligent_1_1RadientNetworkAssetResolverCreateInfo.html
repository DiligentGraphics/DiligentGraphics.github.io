Detailed Description

Configuration of the built-in HTTP/HTTPS resolver. With curl's threaded DNS resolver, cleanup may wait for an OS DNS lookup to finish after either timeout expires. These values do not impose a strict deadline on CheckAsset, OpenAsset, or asset-manager shutdown.

Member Data Documentation

◆ ConnectTimeoutMs

Uint32 Diligent::RadientNetworkAssetResolverCreateInfo::ConnectTimeoutMs = 10000

Connection timeout in milliseconds, including DNS lookup and TLS handshake. On Apple platforms, this is NSURLSession's inactivity timeout: it also applies while waiting for response data and restarts when data arrives. On Android, this limits TCP establishment only. TLS negotiation uses the read timeout derived from the remaining RequestTimeoutMs budget; DNS lookup is controlled by the platform and may outlast either timeout. On the Web, this bounds the wait for response headers instead. Must be nonzero and no greater than INT32_MAX.

◆ MaxRedirects

Uint32 Diligent::RadientNetworkAssetResolverCreateInfo::MaxRedirects = 10

Maximum number of HTTP redirects to follow, no greater than INT32_MAX. Zero disables redirects. On the Web, positive values use the browser limit.

◆ RequestTimeoutMs

Uint32 Diligent::RadientNetworkAssetResolverCreateInfo::RequestTimeoutMs = 60000

Timeout for the network transfer, including redirects, in milliseconds. On Android, the remaining budget supplies the TLS/read timeout and is checked between blocking operations, rather than enforcing a hard deadline. Must be nonzero and no greater than INT32_MAX.
